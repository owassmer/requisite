# 002-1 The public record, retrieved and frozen: regulations.gov into artifacts and items

## Why
Wide discovery (spec §7.2–7.3, outcome 002) reads the public record of affected parties, starting with regulatory
comment dockets. The flow defines its frame from the objective a human approves, reads a sample of items from it, and
everything downstream (judgments, gold labels, prevalence, leads) rests on what it read. So reading has to be exact and
reproducible: every retrieved document becomes an immutable, content-addressed artifact (I2) with its publication and
retrieval times (I3), each item's text is everything its submitter filed, and a replay from the frozen case reproduces
the same items without touching the network. Which dockets the flow reads is decided by the flow at run time (design/
decisions.md, "Discovery finds what it analyzes"); this task builds the machinery that reads whatever it is pointed at.
Nothing in the code may name a particular docket, agency or rule.

## What to build
In `requisite/evidence/` (create it):
- A regulations.gov v4 client: search documents (filters, sort, pagination), get a docket, get a document, list a
  docket's comments (paginated, up to the API's page size), get a comment with its attachments, download an attachment
  file. Every request goes through `requisite.cassettes.call` (provider "regulations_gov"; the endpoint path and the
  query parameters are the cassette key; the key is the X-Api-Key header, from `requisite.secrets`, never in a URL or a
  parameter). Attachment files are fetched with the User-Agent in decisions.md. The key allows 1,000 requests an hour:
  pace by the `x-ratelimit-remaining` header the API returns, so a long read slows rather than fails, and a 429 is waited
  out and retried, never dropped. A request that fails after its retries raises; nothing is skipped silently.
- Artifacts: each comment's API record and each attachment's bytes, committed through the store with published_at from
  the API's postedDate (basis named), observed_at the retrieval time, availability "retrieved". The same content
  retrieved twice is the same artifact; changed content for the same locator is a new artifact linked to its
  predecessor (I2).
- Extraction, versioned and committed (store.commit_extraction): the comment's text with HTML entities decoded and
  whitespace normalized; each PDF attachment's text by its text layer (pypdf), and by OCR for any page without one
  (render the page with poppler's pdftoppm, read it with tesseract; both are installed). The extraction id names the
  method and tool versions, and each page's method is recorded. Other attachment types (Word, images, spreadsheets) are
  read by the right means for each (images by OCR); a file whose text truly cannot be read (a corrupt file) is recorded
  as such on the item with the reason, never dropped from it silently.
- Items: one per comment, in the core Item record: its id, docket, posted time, the submitter's name or organization as
  published, its artifacts, and its text (the comment, then each attachment's text, in order, each marked by where it
  came from).
- The frame, from the definition's `requisite.core.FrameCriteria` (read its docstring) and nothing else: search
  documents of its document types, posted in its window, matching any of its search terms (each term a search, results
  united), in its agencies if it names any; group them by docket; keep dockets whose comment status is as asked (open:
  a document's comment period ends after as_of; closed_pending_final: every comment period has ended by as_of and the
  docket has no document of type Rule posted after its proposal; either: both) and that have at least min_comments
  public comments; then list every comment of the kept dockets posted at or before as_of, by id, docket and posted time,
  from the comment list endpoint (no per-comment request), so a frame of thousands costs tens of requests. The frame
  is a record of what was searched and found (each search's request and count, each docket kept or dropped and why,
  the comment ids), the definition's `requisite.core.Frame`, committed, so the frame is frozen and a replay
  reproduces it.
- Reading a sample: for given comment ids, the full items, fetched in parallel within the rate limit.

## Done
In the running product: `uv run requisite evidence frame --criteria <file> --case <dir>` freezes a frame from criteria
and `uv run requisite evidence read --sample <file> --case <dir>` reads given comment ids into items (or shapes you find
better, named in your report), and running each a second time reads everything from cassettes with no network. Tests in `tests/evidence/` drive the client against the fixture
responses through a transport that serves them (no network in the sandbox; recorded cassettes are the only path),
covering: pagination, the rate-limit wait, a 429 retried, artifact identity and predecessor linking, extraction of the
fixture PDF, OCR of a page with no text layer (make one from the fixture by rasterizing a page), entity decoding,
items assembled in order, frame listing by as_of, and replay with no network. Where anything you build selects
evidence for an instant, it uses the definition's `requisite.core.evidence.observable_at` (I3), never a comparison of
its own. `gates` passes.
