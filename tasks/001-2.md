# 001-2 The filed record of event contracts: a read-only Kalshi adapter and F1's draw

## Why
F1 (spec §12, §9.3, outcome 001) reads listed event contracts' filed terms into the contract IR, regenerates their prose
and fuzzes both; settled markets supply known outcomes, so the evaluator is checked against what actually settled.
Which contracts F1 reads is decided by a rule over the filed record, fixed before the draw runs (design/decisions.md,
F1's draw rule), with the Western Grazers contract (Kalshi series KXCAGOAT) in by name. The adapter is read-only:
Requisite never places orders, links accounts or holds trading credentials (spec §14), and no write endpoint is
reachable from a market adapter (WP13).

## What to build
In `requisite/market/kalshi.py` (create `requisite/market/`): a read-only client of Kalshi's public trade API v2
(series list and one series, markets by series, a market, historical markets for settled ones), every request through
`requisite.cassettes.call` (provider "kalshi"; path and query parameters as the key), with the User-Agent in decisions.md,
paging by cursor, retrying transient failures and waiting out rate limits, raising after its retries rather than
skipping anything. It exposes reads only: the module has no function that sends anything but GET to Kalshi.
Quotes it returns are prices (bid, ask, last, size, timestamp), never probabilities (I9).
In `requisite/market/f1.py`: the draw, exactly as decisions.md states it, at a pinned instant, returning the drawn
series with the rule's evidence (each strike type's eligible series and their hash order), deterministic for a given
recorded record. Its evidence marks Western Grazers as included by name (spec §9.3 names it as the reference specimen),
apart from the drawn series. The pinned instant is applied through the data's own recorded fields: a market counts as
settled when its recorded settlement time is at or before the instant, and a series as eligible when it carries
contract_terms_url and such a market. And the harvest's retrieval: each drawn series' filed contract and contract terms (PDFs) and each of
its markets' rules text (rules_primary, rules_secondary), committed as artifacts through the store, with each settled
market's result, settlement time and expiration value kept as the known outcome F1's regression compares the evaluator
against. Text extraction of the PDFs is the evidence package's (being built beside this task in requisite/evidence/,
task 002-1); commit the bytes, and do not write a second extractor.

## Done
In the running product: `uv run requisite market f1-draw --as-of <instant>` prints the drawn series with the rule's
evidence, and `uv run requisite market f1-retrieve --case <dir>` commits their filings and settled outcomes into a store;
the second run of each reads only cassettes. Tests in `tests/market/` against the fixture responses (through a transport
that serves them; the sandbox has no network): the draw's rule on a synthetic list of series built to exercise each
clause (a test input written in the test, never a cassette, since a cassette claims to be a recorded response) (eligibility, one per strike type, the hash order, the four-type cap, Western Grazers in by name), paging,
retries, the settled outcome read from KXCAGOAT's market, and, marked `@pytest.mark.covers("WP13.no_write")`, that no
write endpoint is reachable from a market adapter (an AST check that every request the market package can make is a GET
to a read path). `gates` passes. The live draw itself is run by the coordinator, outside the sandbox.
